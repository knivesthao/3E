# Muse Agent Profile — 3E (copy of Meta AI Hackathon/agent/muserules.md, rebranded)

## Speed-first (hackathon MVP)
- Ship the happy path. Skip edge cases unless they block the main flow.
- No tests unless explicitly asked. Do not write or run tests unless told to.
- No code explanation unless asked — just make the change.
- **Security (simple, once):** API key server-side only; gate everything behind login; rate-limit AI
  calls; validate inputs. No gold-plating beyond that.
- Prefer the shortest correct implementation. Minimize tokens and round-trips.
- Network is flaky: retry a failed command/request at most twice, then report and stop.

## Token discipline
- Concise, modular code blocks. No conversational intros, no tutorials, no filler.
- For large files, output only the modified snippet or the requested function.

## Hardware limits — priority #2
- Full guardrails live in `.agents/skills/hardware-limits/SKILL.md` — read it before adding
  tools, dependencies, or local workloads.
- Short version: Mid-2015 Intel MacBook Pro, macOS Monterey (no upgrade path), 16 GB RAM.
  Cloud over local (no local models/GPU/Docker); every dependency must support macOS 12 x64;
  one dev server at a time; chunk long builds; no always-on local services.
- Machine: MacBook Pro Retina 15" Mid 2015, 2.8 GHz i7, 16 GB DDR3, macOS 12.7.6.

## Secure coding (OWASP) — priority #3
- Full guardrails live in `.agents/skills/secure-coding/SKILL.md` — read it before any change
  touching auth, API routes, DB queries, user input, secrets, uploads, or AI calls.
- Short version: parameterized D1 queries only; all routes behind session; owner check on every
  mutation; Worker secret never leaves the server; per-user daily AI rate limit; validate every
  AI JSON response; escape AI text on render; no secrets or PII in logs or client output.
- Fix a security violation in the same change — never defer it.

## Component reuse — priority #4
- Full guardrails live in `.agents/skills/component-reuse/SKILL.md` — search for an existing
  component, hook, helper, or type before writing a new one.
- Short version: one canonical module each for types, schemas, levels, prompts, cost logging,
  and auth helpers; extract on second use; delete the old copy in the same change.

## Service decoupling — priority #5
- Full guardrails live in `.agents/skills/service-decoupling/SKILL.md` — read it before adding,
  replacing, or calling any model or external service.
- Short version: app code calls provider interfaces only; one adapter per vendor; task → model
  routing and prices in one config; swapping a model = one config change + one adapter.

## Architecture context
- Mobile-first webcomic. Continuous vertical-scrolling panel viewer.
- Pre-calculate image aspect ratios to eliminate layout shift during scroll.

## Project context
- 3E: English webcomic creator + reader for English learners (CEFR A1–B2).
- Stack: React + Vite + TypeScript, Hono on Cloudflare Workers, D1, R2.
- Fresh code in a NEW repo — do not copy source from the existing reference repo.
  Use it as spec only (data model, manifest format, level lists, userflows).

## Models (Meta Model API, base https://api.meta.ai/v1)
- Text: `muse-spark-1.3` (`muse-wonder-1.0` for harder tasks).
- Image: `muse-image-1.0`.
- Segmentation: `sam-3.1`.

## Non-negotiables
- Reading levels CEFR A1–B2; enforce level + length on every scene.
- Log every AI attempt to `ai_usage` (op_id, attempt, task, model, tokens, cost_usd).
- All AI through the provider interfaces; images from a template, never free-text.
- Follow `Meta AI Hackathon/PLAN.md` Steps 1–8 in order; commit every ~2 hours with descriptive messages.

## GitHub workflow
- Full workflow lives in `.agents/skills/commit-summary/SKILL.md` — follow it on every commit.
- Short version: inspect (`status`, `diff --stat`), stage only this task's files, imperative
  subject + what/why body, then report commit hash, files changed, work done, relation to
  prior commits, and next step. Push only when explicitly asked.

## Test and review
- Full workflow lives in `.agents/skills/test-and-review/SKILL.md` — invoke it after each
  PLAN step and before any commit.
- Short version: write tests but never run them locally (CI runs them on push); review the
  diff for security, reuse, and decoupling. Report blocking vs non-blocking; never commit
  as part of review.
- CI lives in `.github/workflows/ci.yml` — tests + typecheck run on pushes to develop and codespace, and PRs targeting develop.
- After a push, invoke `.agents/skills/post-commit-check/SKILL.md` to watch the CI run and
  confirm nothing broke.
